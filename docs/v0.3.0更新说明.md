# Ktr启停管理工具 v0.3.0 更新说明

## 新增功能

### 1. 循环与结构安全检查

安全校验现在检查：

- 计划启用后的有向数据流是否形成循环；
- hop 引用的来源步骤、目标步骤是否存在；
- 是否存在悬空 hop；
- 是否存在重复步骤名；
- 是否存在重复的 `from → to` hop；
- 分支是否处于部分启用状态。

循环、悬空 hop、缺失步骤、重复步骤名和重复 hop 属于错误，会阻止保存。

分支部分启用属于提示，不直接阻止保存；这是为了继续保留单条 hop 调试能力。

批量启用、双击切换、全部启用或完整分支启用如果新形成循环，本次界面操作会立即自动撤销。

### 2. 保存前变更预览

点击“保存副本”或“备份并覆盖原文件”时：

1. 先执行结构安全检查；
2. 安全检查失败时禁止保存；
3. 安全检查通过后，逐条显示来源步骤、目标步骤、所属分支、原状态和保存后状态；
4. 只有点击“确认并继续保存”才会进入实际文件保存流程。

### 3. 完整分支识别和启停

工具使用 KTR 中的全部 hop 自动计算弱连通分量：忽略箭头方向后，能够相互连通的步骤属于同一个完整分支。

新增按钮：

- “启用所选分支”；
- “停用所选分支”；
- “仅启用所选分支”。

只需选中分支中的任意一条 hop，工具就会操作该分支包含的全部 hop。

列表新增“完整分支”列，筛选器新增“分支部分启用”。

- 71 个完整分支；
- 每个完整分支包含1条 hop；
- 当前启用18条、禁用53条；
- 循环、悬空 hop、缺失步骤、重复步骤名、重复 hop：均未发现。

针对“仅启用门急诊药品医嘱分支”的回归验证：

- 保存后仅1条 hop 启用；
- 共修改17个 `Y/N` 状态字符；
- 文件长度不变；
- 其他字节未发生变化；
- 原始 KTR 未修改。

## 安全边界

- 工具仍然不连接数据库、不执行 KTR。
- 工具仍然只修改 transformation `<order><hop><enabled>` 的 `Y/N`。
- 完整分支识别不等同于业务接口识别；共享步骤会使多条逻辑路径归入同一连通分支。
- 保存结果仍建议先在 Spoon 中重新打开检查，再执行转换。
